# EPUB Reader MVP Implementation Plan (master)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking. This file is the master plan. Milestones M0–M2 have step-level files next to it; M3–M9 are specified
> here at task level and get a step-level file written (with superpowers:writing-plans) when the milestone
> starts, because their design depends on the M0 spike results (see "How this plan is split").

**Goal:** Ship the first usable release of a fast, offline-first, MIT-licensed Android EPUB reader that meets
every MVP requirement in features.md, R-001..R-010, and the measurable "Must" targets of performance.md, with
those targets enforced by an automated benchmark gate on the reference emulator.

**Architecture:** Kotlin Multiplatform (Android target shipping; a JVM target for host tests) with a shared
core (own zip reader, EPUB package parsing, chunker + position mapping, text extraction, Room KMP database
with sync-ready rows, per-book SQLite FTS5 search index) and a Compose Multiplatform UI. Reading is done by
foliate-js in the platform WebView, wrapped in a Vite-built TypeScript host that talks to Kotlin over a typed
JSON bridge; book bytes are served from the zip by a WebView path handler and book scripts are blocked by CSP.
The reader WebView is created at app start and kept alive behind the library so opens are in place.

**Tech Stack:** Kotlin 2.4.20, AGP 9.1.0, Gradle 9.3.1, compile/target SDK 37, minSdk 26, Room KMP +
androidx.sqlite bundled driver (FTS5), kotlinx.coroutines, kotlinx.serialization, Compose
Multiplatform + Material 3, Jetbrains navigation-compose, Coil 3, WorkManager, androidx.webkit,
TypeScript + Vite + Vitest, foliate-js @ `78914aef4466eb960965702401634c2cb348e9b1` (vendored, patched).

**Spec:** `~/Projects/epub-reader-spec/features.md` (v0.2), `performance.md` (v0.3), `corpus.md`,
`HANDOFF_LOG.md`; decisions in `docs/decisions/0001-stack.md`; engine evidence in `docs/engine-evaluation.md`.
Executors read the spec files and the ADR before starting any milestone.

- Downloaded corpus files are untrusted: never execute anything from inside `corpus/`; run Python that reads them with `python3 -I`.

## Review Focus

Inputs the spec implies but does not test directly; each has a pinning test in the owning task.

1. **Kotlin canonical text ≠ DOM text** (CRLF in source, entities like `&nbsp;`, CDATA, `<script>`/`<style>`
   text, documents the browser had to re-parse as HTML). Expected: a search hit opens on the exact word, or within
   the same paragraph. Pinned by: M2 Task 2.6 (`TextExtractorTest.crlf_entities_cdata_script`) and M6 Task 6.3
   (fuzzy re-match test `resolve_offset_drifted_by_whitespace`).
2. **Open-with from a `content://` provider that has no file path** (Downloads provider, mail attachment,
   cloud app). Expected: the book opens and is remembered. Pinned by: M4 Task 4.6 (`OpenWithTest.contentUriWithoutPath`).
3. **Chunk policy changes between app versions** (threshold or part size changed, or chunk cache deleted).
   Expected: saved position, bookmarks and highlights in a huge chapter land on the same text. Pinned by: M2 Task
   2.8 (`ChunkMapTest.position_survives_policy_change`).
4. **A different book written to the same path** (user replaces `book.epub` with another edition or another book).
   Expected: no reading data from the old book is attached to the new one; the old entry disappears.
   Pinned by: M4 Task 4.2 (`ScannerTest.same_path_different_content`).
5. **App killed during the first scan or during search indexing.** Expected: next start resumes, no duplicate
   books, no half-built index used as complete. Pinned by: M4 Task 4.2 (`ScannerTest.interrupted_scan_resumes`)
   and M6 Task 6.1 (`IndexBuilderTest.resume_after_kill`).

## Architecture

### Module map

```
epub-reader/
  settings.gradle.kts, build.gradle.kts, gradle/libs.versions.toml, gradle.properties
  core/epub/      KMP (android + jvm). Zip reader, package/TOC parsing, metadata/cover/identity, markup scanner,
                  text extraction, chunker, CFI + chunk position mapping. No Android APIs in commonMain.
  core/data/      KMP (android + jvm). Room KMP database (sync-ready rows), DAOs, repositories, clock/ids,
                  settings store, backup format (kotlinx.serialization JSON).
  core/search/    KMP (android + jvm). Per-book FTS5 index files via androidx.sqlite bundled driver, index
                  builder, query engine, result streaming.
  ui/             KMP (android) Compose Multiplatform + Material 3: design tokens, library, reader chrome,
                  panels, settings. Pure UI + view models; platform services injected.
  reader-web/     TypeScript + Vite + Vitest: host page, bridge, foliate-js vendored + patches, page counter.
                  Build output is copied into app assets (`app/build/generated/readerAssets/reader/`).
  app/            Android application: MainActivity (single activity), ReaderEngine (pre-warmed WebView),
                  BookContentServer, storage walker, intents, WorkManager, flavors play/fdroid,
                  `benchmark` build type (Probe events + BenchCommandReceiver).
  baselineprofile/ (M9) Baseline Profile generator module.
  bench/          Benchmark harness: scripts, targets.json, baseline.json, gate.py, results/.
  spikes/         M0 throwaway spike app (copy of prototypes/foliate); never a dependency of production code.
  tools/          Bake-off tools (kept); corpus.sh (M1).
  docs/           decisions/, plans/, spikes/, licenses.md, bridge-protocol.md
```

Dependency direction: `app → ui → core:data, core:search, core:epub`; `core:search → core:epub`;
`core:data` does not depend on `core:search`. `reader-web` is independent and talks only through the bridge.

### Runtime flow (opening a book)

1. App start: `MainActivity` shows the library from Room; after the first frame, `ReaderEngine.prewarm()` creates
   the WebView, loads `https://appassets.androidplatform.net/reader/index.html` (host page + foliate-js modules).
2. Tap a book: reader route shows instantly (frame + progress indicator, P-015); `BookOpener` (IO dispatcher)
   opens `ZipReader`, loads `BookPackage` (cached), runs/loads the chunk cache, registers a `BookSession` with
   `BookContentServer`, then sends `open{sessionId, lastPosition(virtual CFI)}` to JS.
3. JS host loads entries via `/book/<sessionId>/…`, foliate opens, preloads neighbours, paints, emits `relocate`.
4. Kotlin maps the virtual CFI to the original CFI (`ChunkMap`) and writes `reading_position` transactionally.

### Key cross-module interfaces (names fixed here; tasks must use them)

```kotlin
// core:epub
interface RandomAccessSource : AutoCloseable { val size: Long; fun read(position: Long, dst: ByteArray, off: Int, len: Int): Int }
class ZipReader { companion object { fun open(src: RandomAccessSource): ZipReader }; val entries: List<ZipEntry>;
  val centralDirectoryDigest: String; fun entry(path: String): ZipEntry?; fun readBytes(e: ZipEntry, limit: Long = 64L shl 20): ByteArray;
  fun openStream(e: ZipEntry): ByteStream }
object PackageLoader { fun load(zip: ZipReader): LoadResult }       // LoadResult.Ok(BookPackage, warnings) | LoadResult.Failed(FailReason, detail)
enum class FailReason { NOT_A_ZIP, DAMAGED_ARCHIVE, NO_PACKAGE, BROKEN_PACKAGE, NOTHING_READABLE }
object BookIdentity { fun of(uniqueId: String?, centralDirectoryDigest: String): String }   // "<16 hex sha256(uniqueId)>-<32 hex cd digest>"
object TextExtractor { fun extract(markup: String, cuts: IntArray = IntArray(0)): ExtractedText }  // canonical text + segments + markup→text offsets
class Chunker(policy: ChunkPolicy) { fun chunk(zip: ZipReader, pkg: BookPackage, cache: ChunkStore): ChunkedBook }
class ChunkMap { fun cfiToOriginal(virtualCfi: String): String; fun cfiToVirtual(originalCfi: String): String;
  fun hrefToVirtual(originalHref: String): String; fun hrefToOriginal(virtualHref: String): String;
  fun textToVirtual(pos: TextPos): TextPos; fun textToOriginal(pos: TextPos): TextPos }
data class TextPos(val spineIndex: Int, val offset: Int)

// core:data  (all synced entities extend the same columns)
//   id: String (UUID v4 text), updatedAt: Long (HybridClock ms, monotonic), deleted: Boolean (tombstone)
// core:search
class SearchIndex { suspend fun ensureBuilt(book: IndexableBook, progress: (Int) -> Unit) }
class SearchEngine { fun search(bookId: String, query: SearchQuery): Flow<SearchBatch> }  // streaming, capped at 5000
```

TypeScript bridge (detailed in M1 Task 1.3 and `docs/bridge-protocol.md`): Kotlin→JS
`window.__reader.receive(json)`; JS→Kotlin `WebViewCompat.addWebMessageListener` object `ReaderBridge`
restricted to origin `https://appassets.androidplatform.net`. Every message is `{ "v": 1, "type": "...", ... }`.

## Open questions for the gatekeeper (with proposed defaults)

Q1. **F-050 match mode.** "Case-insensitive … diacritic-insensitive … with an option for whole-word matching" does
not say whether the default matches inside words. *Default:* default mode matches words **starting with** the query
(FTS5 prefix), whole-word mode matches exact words; no mid-word substring matching.

Q2. **F-034 in scrolled mode.** What is "page N of M" while scrolling? *Default:* show the paged-mode page number for
the current position (same totals), so the indicator does not jump when switching modes.

Q3. **P-021 "exact".** If the background counter's per-section page counts can differ from what the visible
paginator shows (e.g. ±1 page in rare sections), is that acceptable? *Default:* "exact" = produced by the same layout
engine at the same settings; any visible disagreement is a bug; the total is labelled exact only after all sections
are counted.

Q4. **F-031 automatic mode.** "automatic (paged in portrait)" — what in landscape? *Default:* scrolled in landscape.

Q5. **F-032 volume keys default.** *Default:* off; when turned on, volume-down = next page, with "reversed" giving the
reference mapping.

Q6. **F-024 vs F-027.** F-024 (MVP) lists "export annotations" as a multi-select action, but export itself is F-027
(Later). *Default:* omit the export action from the MVP.

Q7. **F-100 lists Later settings** (sync, open last book on launch). *Default:* not shown in the MVP.

Q8. **All-files access (F-010) on Play.** Whole-storage discovery without the media index requires
`MANAGE_EXTERNAL_STORAGE` on Android 11+, which Play restricts. *Default:* request it in both flavors for the MVP;
revisit with F-002 before a Play release.

Q9. **F-012 identity when a file is updated in place.** A new version of the same edition (same package identifier,
same path, different content) becomes a new book under content identity. *Default:* if the old file's path now holds
content with the **same package identifier**, move the reading data to the new identity (positions may drift
slightly); different identifier → new book (Review Focus 4).

Q10. **Real-device checks.** P-025 (animation ≤ 300 ms) and P-027 (p90 ≤ 16.7 ms) name a real device. *Default:*
emulator gates only (no blank/partial frame; frame times no worse than the reference-relative rule); real-device
results recorded manually when a device is provided; not a release blocker unless the gatekeeper says so.

Q11. **F-090 restore semantics.** Replace all local reading data, or merge? *Default:* merge per row by `updatedAt`
(newest wins), tombstones respected, books not on the device kept as pending identities and attached when found.

Q12. **P-027/P-031 "no worse than reference / baseline".** *Default:* p90 frame time ≤ 1.3 × the Settings-app p90
measured in the same emulator session.

Q13. **App name and applicationId.** Not in the spec. *Default:* `app.epubreader` until the product name is chosen
(changing it after a store release is costly).

Q14. **P-016 base.** "≤ 50 % of P-010..P-014": of our own first-open median or of the Must value? *Default:* of our own
measured first-open median for that book, and never above 400 ms stretch as a goal.

Questions raised by M0 (for the gatekeeper; details in `docs/spikes/S1-page-totals.md`):

- Q-S1-1. **P-021 for books larger than War and Peace.** The exact total took 2.9–4.2 s for W&P (≈ 60–85 % of the
  budget); it scales with text size, so much longer books (Shakespeare complete, Linear Algebra) will likely exceed
  5 s. *Proposed:* the 5 s gate applies to W&P as written; for other books "≈ N" (±5 %) until exact, no time limit.
- Q-S1-2. **The first 0.2–0.4 s after a layout change**, before the first estimate exists. *Proposed:* show
  "page N" without a total (or the previous total prefixed with "≈") during that window.

## Decisions taken in this plan (please confirm with the user)

- A KMP **JVM target** is added to the core modules and `ui` for fast host tests; no desktop app is built.
- No XML library: one own lenient markup scanner serves OPF/NCX/nav parsing, text extraction and chunking, so
  all three agree on structure (M2 Task 2.2).
- Own zip reader instead of `java.util.zip.ZipFile`: needed for central-directory identity hashing, fd-based
  `content://` sources and KMP portability. Verified against the whole corpus in M2.
- One FTS5 database file per book (cheap delete, no cross-book filtering, rebuildable cache, excluded from backup).
- Identity = package unique-identifier + digest of the zip central directory (no full-file hash during scans).
