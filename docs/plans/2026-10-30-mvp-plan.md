**Goal:** Ship the first usable release of a fast, offline-first, MIT-licensed Android EPUB reader that meets
every MVP requirement in features.md, R-001..R-010, and the Must targets of performance.md. The Must targets are
checked by a benchmark suite on the reference emulator at the end of each milestone and before release
(C-015), and the frame-time targets once on a real device.

**Architecture:** Kotlin Multiplatform (Android target shipping; a JVM target for host tests) with a shared
core (own zip reader, later EPUB package parsing, text extraction, chunker + position mapping), Room KMP database
with sync-ready rows, per-book SQLite FTS5 search index, and a Compose Multiplatform UI. Reading is done by
foliate-js in the platform WebView, wrapped in a Vite-built TypeScript host that talks to Kotlin over a typed
JSON bridge. foliate-js parses the package, TOC and CFIs of the open book. Book bytes are served from the zip by
a WebView path handler, and book scripts are blocked by CSP. The reader WebView is created at app start and kept
attached behind the home/library screen, so opens happen in place.

**Tech Stack:** Kotlin 2.4.20, AGP 9.1.0, Gradle 9.3.1, compile/target SDK 37, minSdk 26, Room KMP +
androidx.sqlite bundled driver (FTS5), kotlinx.coroutines, kotlinx.serialization, Compose
Multiplatform + Material 3, Coil 3, WorkManager, androidx.webkit,
TypeScript + Vite + Vitest, foliate-js @ `78914aef4466eb960965702401634c2cb348e9b1` (vendored, patched).

**Spec:** `~/Projects/epub-reader-spec/features.md` (v0.2), `performance.md` (v0.5), `corpus.md`,
`clarifications.md` (C-001..C-017), `HANDOFF_LOG.md`; decisions in `docs/decisions/0001-stack.md`; engine
evidence in `docs/engine-evaluation.md`; M0 results in `docs/spikes/`. Executors read the spec files and the ADR
before starting any milestone.

- No billing code in the MVP; only the `BillingGateway` seam.
- F-092: "No network access is needed for reading; no analytics without opt-in." The MVP has no analytics and
  no network code except opening external links in the browser (F-044).
- F-110: "Everything in sections A–K works with no account and no network."
- F-115: local data "stored with stable IDs, change timestamps and deletion markers from day one".
- R-005: "Parsing, scanning, search, cover extraction and pagination never run on the UI thread … Back always works within 200 ms."
- R-007: "Scripts in content are disabled by default". The host page CSP `script-src 'self'` enforces this.
- R-009: "Reading positions, bookmarks and highlights are written transactionally; killing the app at any moment
  loses at most the last page change. Backups are versioned".
- Reading positions, bookmarks and highlights are stored against **original** documents (never chunk parts).
  From M2 on, every position that crosses between the reader and storage goes through `PositionMap`. Until M8 this
  is the identity map; in M8 the chunker's `ChunkMap` replaces it.
- **Database versions (revision 2):** the user reads with development builds from M2 on, so every schema change
  from M2 on bumps the Room version with an `AutoMigration` (schemas exported in `core/data/schemas/`). Reading
  data is never dropped by an upgrade.
- **Performance (C-015):** only performance.md **Must** values are targets. Each value is a **median of at least
  3 runs** on AVD "Medium_Phone" (API 37, 1080×2400 @ 420 dpi, 2 GB configured RAM, 4 vCPUs), measured with the
  methods in performance.md "Measurement methods". The full suite (`bench/run_all.sh` with every group built so far)
  runs at the end of each milestone, and the release suite runs in M9. A milestone does not close with a red gate
  for a target it owns. The per-build check is `tools/smoke.sh` (host tests + one instrumented smoke test, a few

- Device control: emulator host id `local`, device `Medium_Phone`, via the T3 device tools (`device_open` returns
  the `agent-device` command, exported to the harness as `AD`). Taps, text entry and screen recordings go through
  `$AD`; `adb` is used only for installs, logcat, `am start -W` timing, `am broadcast` bench commands, `dumpsys`,
  `appops`, and pushing the corpus (the project's test runner).
- Downloaded corpus files are untrusted: never execute anything from inside `corpus/`; run Python that reads them with `python3 -I`.

## Review Focus

Inputs the spec implies but does not test directly; each has a pinning test in the owning task.

1. **Kotlin canonical text ≠ DOM text** (CRLF in source, entities like `&nbsp;`, CDATA, `<script>`/`<style>`
   text, documents the browser had to re-parse as HTML). Expected: a search hit opens on the exact word, or within
   the same paragraph. Pinned by: M4 Task 4.6 (`TextExtractorTest.crlf_entities_cdata_script`) and M5 Task 5.3
   (fuzzy re-match test `resolve_offset_drifted_by_whitespace`).
2. **A `content://` source that has no file path** (picker result from a cloud provider, Downloads provider, mail
   attachment). Expected: the book opens and is remembered. Pinned by: M2 Task 2.3
   (`BookSourcesTest.pipe_is_copied_then_opened`) and M3 Task 3.9 (`OpenWithTest.contentUriWithoutPath`).
3. **Chunk policy changes between app versions** (threshold or part size changed, or chunk cache deleted).
   Expected: saved position, bookmarks and highlights in a huge chapter land on the same text. Pinned by: M8 Task
   8.2 (`ChunkMapTest.position_survives_policy_change`).
4. **A different book written to the same path** (user replaces `book.epub` with another edition or another book).
   Expected: no reading data from the old book is attached to the new one; the old entry disappears.
   Pinned by: M3 Task 3.5 (`ScannerTest.same_path_different_content`).
5. **App killed during the first scan or during search indexing.** Expected: next start resumes, no duplicate
   books, no half-built index used as complete. Pinned by: M3 Task 3.5 (`ScannerTest.interrupted_scan_resumes`)
   and M5 Task 5.1 (`IndexBuilderTest.resume_after_kill`).
6. **(rev. 2) Identity computed from two parsers.** In M2 the package identifier comes from foliate-js
   (`opened.identifier`); from M3 on the scanner computes it in Kotlin. If they differ, a book read in M2 shows up
   twice and loses its position. Expected: both produce the same identifier (whitespace collapsed and trimmed).
   Pinned by: M3 Task 3.3 (`IdentityAgreementTest`, whole corpus).
7. **(rev. 2) Touches between Compose and the WebView behind it.** The WebView stays attached under the home and
   library screens. Expected: taps on Compose chrome (buttons, panels) never reach the book; swipes on the reader
   with hidden chrome always turn the page. Pinned by: M2 Task 2.5 (`ReaderTouchTest`).

## Architecture

### Module map

```
epub-reader/
  settings.gradle.kts, build.gradle.kts, gradle/libs.versions.toml, gradle.properties
  core/epub/      KMP (android + jvm). Zip reader + BookIdentity (M2); markup scanner, package/metadata/cover
                  (M3); text extraction (M4); CFI + ChunkMap + chunker (M8). No Android APIs in commonMain.
  core/data/      KMP (android + jvm). Room KMP database (sync-ready rows), DAOs, repositories, clock/ids,
                  position writer, settings store, backup format (kotlinx.serialization JSON).
  core/search/    KMP (android + jvm). Per-book FTS5 index files via androidx.sqlite bundled driver, index
                  builder, query engine, result streaming (M5).
  ui/             KMP (android + jvm tests) Compose Multiplatform + Material 3: theme, home/library, reader chrome,
                  panels, settings. Pure UI + state holders; platform services injected through ports.
  reader-web/     TypeScript + Vite + Vitest: host page, bridge, foliate-js vendored + patches, page counter (M4).
                  Build output is copied into app assets (`assets/reader/`).
  app/            Android application: MainActivity (single activity), ReaderEngine (pre-warmed WebView kept
                  behind the home screen), BookOpener, BookContentServer, storage walker (M3), intents, WorkManager,
                  flavors play/fdroid, `benchmark` build type (Probe events + BenchCommandReceiver).
  bench/          Milestone benchmark suite: scripts, targets.json, gate.py, results/ (gitignored).
  spikes/         M0 throwaway spike app; never a dependency of production code. Source of the S1/S2 patches.
  tools/          Bake-off tools (kept); corpus.sh, smoke.sh (M1).
  docs/           decisions/, plans/, spikes/, milestones/, licenses.md, bridge-protocol.md
```

Dependency direction: `app → ui → core:data, core:search, core:epub`; `core:search → core:epub`;
`core:data → core:epub`; `core:data` does not depend on `core:search`. `reader-web` is independent and talks only
through the bridge.

### Runtime flow (opening a book)

1. App start: `MainActivity` composes the home screen (M2: recent books; M3: library) over the reader surface.
   After the first frame, `ReaderEngine.prewarm()` creates the WebView (full size, behind the home screen) and
   loads `https://appassets.androidplatform.net/assets/reader/index.html` (host page + foliate-js modules).
2. Tap a book (or pick one): the reader route shows at once (chrome + progress indicator, P-015). `BookOpener`
   (IO dispatcher) opens the `RandomAccessSource` (file path or `content://` descriptor) and `ZipReader`, and
   registers a `BookSession` with `BookContentServer`. Then `ReaderController` sends
   `open{sessionId, position}`. M8 adds the chunk cache here.
3. JS host lists entries via `/book/<sessionId>/entries.json`, foliate parses the package and posts
   `opened{identifier, title, toc, …}`, then paints and emits `relocate`. M4 adds neighbour preloading.
4. Kotlin computes the book identity (`BookIdentity.of(identifier, cdDigest)`), records the book, maps the CFI
   through `PositionMap` to the original document, and writes `reading_position` transactionally.

### Key cross-module interfaces (names fixed here; tasks must use them)

```kotlin
// core:epub
interface RandomAccessSource : AutoCloseable { val size: Long; fun read(position: Long, dst: ByteArray, off: Int, len: Int): Int }
class ZipReader { companion object { fun open(src: RandomAccessSource): ZipReader }; val entries: List<ZipEntry>;
  val centralDirectoryDigest: String; fun entry(path: String): ZipEntry?; fun readBytes(e: ZipEntry, limit: Long = 64L shl 20): ByteArray;
  fun openStream(e: ZipEntry): ByteStream }                                                        // M2
object BookIdentity { fun of(uniqueId: String?, centralDirectoryDigest: String): String }          // M2; "<16 hex sha256(uniqueId)>-<32 hex cd digest>"
interface PositionMap { fun cfiToOriginal(virtualCfi: String): String; fun cfiToVirtual(originalCfi: String): String }  // M2 (identity impl)
object PackageLoader { fun load(zip: ZipReader): LoadResult }       // M3; LoadResult.Ok(BookPackage, warnings) | LoadResult.Failed(FailReason, detail)
enum class FailReason { NOT_A_ZIP, DAMAGED_ARCHIVE, NO_PACKAGE, BROKEN_PACKAGE, NOTHING_READABLE }  // M3
object TextExtractor { fun extract(markup: String, cuts: IntArray = IntArray(0)): ExtractedText }  // M4
class ChunkMap : PositionMap { fun hrefToVirtual(originalHref: String): String; fun hrefToOriginal(virtualHref: String): String;
  fun textToVirtual(pos: TextPos): TextPos; fun textToOriginal(pos: TextPos): TextPos }               // M8 (M5 adds text mapping to PositionMap, identity)
data class TextPos(val spineIndex: Int, val offset: Int)

// core:data  (all synced entities extend the same columns)
//   id: String (UUID v4 text), updatedAt: Long (HybridClock ms, monotonic), deleted: Boolean (tombstone)
sealed interface SourceRef { val key: String }   // File(path) | Content(uri); key = path or URI string  (M2)
// core:search (M5)
class SearchIndex { suspend fun ensureBuilt(book: IndexableBook, progress: (Int) -> Unit) }
class SearchEngine { fun search(bookId: String, query: SearchQuery): Flow<SearchBatch> }  // streaming, capped at 5000
```

TypeScript bridge (M1 Task 1.3 v0, M2 Task 2.4 v1 subset, `docs/bridge-protocol.md`): Kotlin→JS
`window.__reader.receive(json)`; JS→Kotlin `WebViewCompat.addWebMessageListener` object `ReaderBridge`
restricted to origin `https://appassets.androidplatform.net`. Every message is `{ "v": 1, "type": "...", ... }`.
Messages are added by the milestone that needs them; unknown types are ignored on both sides.

## Open questions for the gatekeeper (with proposed defaults)

R2-1. **C-010 vs C-015 for P-025/P-027.** C-010 says "emulator gates only for the MVP" with a real-device pass
before the first public release. C-015 says frame-time/jank targets are "checked once on a real device before
release, not gated on the emulator". *Proposed default:* C-015 is newer and wins: no emulator frame-time or
blank-frame gate for P-025/P-027, and C-012's Settings-baseline rule is no longer used. One real-device pass in
M9 Task 9.3. The P-026 blank-frame check (boundary turns) stays an emulator gate because P-026 is not a
frame-time target.

R2-2. **Other smoothness clauses.** P-031 ("scroll without dropped frames beyond baseline") and P-063 ("no visible
stalls") are jank-type clauses that C-015 does not name. *Proposed default:* treat them like P-025/P-027 and check
them on the real device in M9. P-031's "≤ 200 ms to open the panel" stays an emulator milestone gate (M2).

R2-3. **Which targets count as "edge-case" (C-015 "and similar").** *Proposed default:* release checks in M9 are
P-014, P-023, P-044, P-061, P-062, P-063, R-006, and the corpus-wide parts of P-021 (agreement and ±5 % estimate
for every book). P-012/P-013 (2000-chapter and 200-image open) stay milestone gates. They use stress books, but
the open group measures them at no extra cost and the bake-off already met them.

R2-4. **Release without a real device.** C-010 requires a real-device pass before the first public release, and
the plan has no device yet. *Proposed default:* M9 can close with "real-device pass pending", and the first public
release waits until it is done. Internal/test builds are not blocked.

R2-5. **Can the exact page total (P-021) be missing at release?** C-015 says "the '≈ N' estimate may ship first
and the exact total can follow", while performance.md keeps "≤ 5 s exact for War and Peace" as a Must (a release
blocker). *Proposed default:* "ship first" means "land in an earlier milestone": the exact total is still
required before the first public release. S1 shows it fits (2.9–4.2 s). If the gatekeeper means the MVP may ship
without it, Task 4.8 moves after M9.

## Decisions taken in this plan (please confirm with the user)

- A KMP **JVM target** is added to the core modules and `ui` for fast host tests; no desktop app is built.
- No XML library: one own lenient markup scanner serves OPF/NCX parsing, text extraction and chunking, so
  all three agree on structure (M3 Task 3.1).
- Own zip reader instead of `java.util.zip.ZipFile`: needed for central-directory identity hashing, fd-based
  `content://` sources (the M2 picker) and KMP portability.
- One FTS5 database file per book (cheap delete, no cross-book filtering, rebuildable cache, excluded from backup).
- Identity = package unique-identifier + digest of the zip central directory (no full-file hash during scans).
- (rev. 2) The reader's own parse (foliate-js) is the source of the open book's TOC and, in M2, of its identifier.
  Kotlin parses packages only for the library, search and chunking. No Kotlin TOC parser.
- (rev. 2) The reader WebView stays attached, full size, behind the home/library screen (as in the bake-off's
  in-place mode), so foliate always has a real viewport. There is no re-parenting.
- (rev. 2) Navigation is a small route stack in `ui` (Home, Reader); navigation-compose is not used.
- (rev. 2) Room schema changes from M2 on ship with AutoMigrations, so reading data survives development builds.
